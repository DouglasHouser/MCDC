**Breakdown by function:**
- `interface.py` - High-level transport API
  - `compton_scatter()`
  - `pair_production()`

  - Cross-section lookups

- `cross_sections.py` - All cross-section calculations

  - `photoelectric_total(element, E)`
  - `pair_production_total(element, E)`
  - `total_cross_section(element, E)`

- `distributions.py` - Scattering kernels
  - `sample_klein_nishina(E_in)`
  - `sample_pair_production(E_gamma)`
  - `sample_photoelectric_shell(E_photon)`

- `native.py` - Data management
  - `load_nist_xcom()`
  - Data caching

- `util.py` - Helpers
  - Numerical integration
  - Constants
  - Special functions

## File Organization Strategy

### Principle 1: Separate By Concern
```
Physics module (cross_sections.py)
  ├─ One file per major concept (not one file per reaction)
  ├─ Klein-Nishina: formula + integration
  ├─ Photoelectric: tabulated lookup
  └─ Pair production: threshold + kinematics

Tests (one file per component)
  ├─ test_klein_nishina.py
  ├─ test_photoelectric.py
  ├─ test_pair_production.py
  └─ test_compton_kernel.py
```

### Principle 2: Follow Neutron Patterns
```
Neutron transport:
  mcdc/transport/physics/neutron/
  ├── interface.py
  ├── native.py
  ├── multigroup.py

Photon transport (mirror structure):
  mcdc/transport/physics/photon/
  ├── interface.py         ← Same pattern
  ├── native.py            ← Same pattern
  ├── cross_sections.py    ← Like neutron reactions
  ├── distributions.py     ← Like neutron distributions
  └── util.py              ← Helpers
```

### Principle 3: Use Code Factory Pattern
```
User-facing setters (auto-generated):
  mcdc/mcdc_set/photon_material.py

Internal getters (auto-generated):
  mcdc/mcdc_get/photon_material.py

Advantage: Leverage existing boilerplate generator, stay consistent
```

## Recommended File Naming Convention

### Physics Module
```
✅ GOOD:
  cross_sections.py         (what it does)
  distributions.py          (what it does)
  interface.py              (public API)

❌ AVOID:
  photon_physics.py         (too vague)
  interactions.py           (what interactions?)
  physics_core.py           (redundant)
```

### Tests
```
✅ GOOD:
  test_klein_nishina.py     (tests what)
  test_photoelectric.py     (tests what)
  test_integration_transport.py (tests what + where)

❌ AVOID:
  test_photon.py            (too broad)
  test_phase2.py            (don't organize by phase in code)
  test_cross_sections_all.py (redundant "all")
```

### Examples
```
✅ GOOD:
  photon_transport_absorption/input.py     (what it demos)
  photon_transport_compton/input.py        (what it demos)
  photon_transport_pair_production/input.py (what it demos)

❌ AVOID:
  photon_example_1.py       (meaningless number)
  test_example_absorption.py (examples aren't tests)
  demo_photon.py            (vague)
```

## Anti-Patterns to Avoid

### ❌ Don't Split Physics Into Too Many Files
```
❌ WRONG:
  mcdc/transport/physics/photon/
  ├── compton_scattering.py
  ├── photoelectric_absorption.py
  ├── pair_production.py
  ├── compton_differential.py
  ├── pair_kinematics.py
  ├── pe_shell_selection.py
  ... (10+ files)

✅ CORRECT:
  mcdc/transport/physics/photon/
  ├── cross_sections.py      (all σ in one place)
  └── distributions.py       (all kernels in one place)
```

### ❌ Don't Duplicate Between Unit & Regression
```
❌ WRONG:
  test/unit/photon/test_klein_nishina_validation.py
  test/regression/photon/test_klein_nishina_validation.py (duplicate!)

✅ CORRECT:
  test/unit/photon/test_klein_nishina.py       (unit tests)
  test/regression/photon/test_compton_spectrum.py (integration test)
```

### ❌ Don't Create One Test File Per Reaction Type
```
❌ WRONG:
  test/unit/photon/
  ├── test_compton.py
  ├── test_pe.py
  ├── test_pair.py
  └── test_rayleigh.py (4 files, 200 LOC each)

✅ CORRECT:
  test/unit/photon/
  ├── test_klein_nishina.py  (300 LOC)
  ├── test_photoelectric.py  (250 LOC)
  └── test_pair_production.py (280 LOC)
```
